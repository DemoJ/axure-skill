# 可选精细检查

仅在用户明确要求对原型检查、测试、验收、验证或截图核对时使用本流程。默认生成和交付 RP/HTML 无需读取本文件，也不执行下列步骤。具体测试字段见 [interactions.md](interactions.md#真实-html-运行测试)。

## 按用户要求确定范围

- 只要求视觉检查：检查指定页面/状态的截图、排版、居中和溢出，不自动遍历所有交互。
- 只要求交互测试：运行指定或关键流程，不自动进行多轮视觉微调。
- 要求完整验收：覆盖主要页面/状态的视觉和关键交互路径。
- 修改已生成原型：沿用原工程或 spec，优先检查受影响部分；不因开启检查而重新设计整个原型。

## 视觉与运行检查

1. 已生成 RP 时沿用它；需要浏览器检查且尚无 HTML 时再导出。`create` 已含原生保存/回读，不重复运行相同的 `inspect` 或 `verify`。
2. 无头检查前运行 `node "$axureSkill\scripts\runtime_test.cjs" --doctor` 查询已有 Playwright/Chromium，缺少时再按实际需要配置，不重复安装。
3. 用一次配套测试计划覆盖所需路径，在同一次浏览器运行中保存关键状态截图；先汇总问题再集中修复，修复后复查受影响流程和画面。
4. 固定宽度原型按检查范围核对目标手机/页面宽度和桌面宽屏的 HTML，确认居中且同宽时无意外水平滚动；用户实际使用 Axure 播放器时再检查其内容区。原生居中导出会消除正的起始 x 偏移，不要用额外背景或占位控件撑出编辑区。
5. 报告实际完成的检查、发现的问题和限制；未运行的项目不声称通过。不以新增业务页或重复全量截图代替视觉完善。

测试 step 的 `screenshot:"screenshots/login-phone.png"` 可直接保存多张截图，路径相对测试计划；加 `screenshot_target:"画面面板ID"` 直接截取画面，避免 fullPage 包含原生编辑偏移后还要手工裁剪。保留所需宽屏截图和页面对齐断言检查外围布局，无需另写 shots/capture 脚本。测试仅使用浏览器内部输入，不移动桌面鼠标。

## 官方 API 与原生 PNG

只有用户要求的检查需要独立 API 核验/原生 PNG 且 `doctor.official_read_api:true` 时，运行 `verify FILE --render-dir DIR`。API 缺失时报告该项不可用，不阻塞 RP/HTML 交付，也不自动下载它。

**官方 API 的整页 PNG 会漏画动态面板内容**；单独状态 PNG 可以显示该状态。需要完整复杂预览的截图时，使用真实 HTML 的无头浏览器截图，不能把空白区域当作工程正常的证据。
